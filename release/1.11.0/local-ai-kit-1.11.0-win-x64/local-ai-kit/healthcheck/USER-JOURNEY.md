# 用户链路审计：从「点下载」到「能用」，以及「变笨了怎么办」

> 审计对象：本仓库（local-ai-kit）的实际代码，不是 README 的承诺。
> 每个结论都标了代码位置，可复核。

---

## 0. 结论先说

**链路本身是通的**——下载 → 双击 → 向导 → 桌面图标 → 工作台，这条主干没有断点。

**断在"出问题之后"**：整套流程只设计了「装不上怎么办」，没有设计「装上了但不好用怎么办」。
而后者才是用户真正会遇到的——模型跑起来了、能对话了，只是回答变短、长对话跑偏。

三条最严重的问题：

| # | 问题 | 后果 |
|---|---|---|
| **P1** | 体检工具需要 Python，但本包承诺"只要 Node"、且安装器只装 Node | 走完一键安装的用户**根本跑不了体检**（已修：新增 Node 版 `quick.mjs`） |
| **P2** | 控制台能删掉正在使用的模型，且**不回写配置** | 删了 → 启动失败 → 装新的 → 配置还指向旧的 → **死循环，没有出口**（已加护栏） |
| **P3** | 使用界面（工作台）里**没有任何配置入口** | 想改上下文/压缩，只能重跑整个安装向导。**v1.3.6 起改到控制台**（工作台本身仍无入口） |

## 2. 修正工具应该嵌在哪

原则：**用户不会主动去找工具，工具要出现在他正难受的那个位置。**

### E1 · 安装完成页 → 「跑一次体检」（推荐优先做）

位置：`ui/index.html` 的 `view-done`，在「立即启动工作台」旁边加一个次级按钮。

为什么这里最合适：
- 用户此刻**刚装完、有耐心、显存空着**，跑一次 43 秒的体检成本最低；
- 这次结果会成为**基线**，以后任何"变笨"的抱怨都能对比；
- 没有基线的话，后面所有数字都不可解释——这正是 R8 那条"无法判定"的根源。

实现：按钮 → `POST /api/health` → 控制台已有的 SSE 通道回传进度 → 完成后在页面上显示三个判据。

### E2 · 控制台新增「体检」页（**已实现，v1.3.7**）

位置：`ui/console.html` 的 `#tabs` 加第三项，`scripts/console.mjs` 加 `/api/health`。

为什么在这里：
- 控制台是**唯一长期存在的本地 UI**（工作台是第三方的，启动器窗口关了就没）；
- 用户遇到"变笨"时的自然动作是打开控制台看看，而不是重跑安装向导；
- 复用现有 SSE（`/api/events`）就能流式显示进度，不用新机制。

### E3 · 控制台模型页 → 标记「当前使用」并拦住误删

位置：`/api/state` 返回 `active: name === cfg.model`，`ui/console.js` 渲染徽章；
`/api/delete` 拦掉当前模型（已实现）。

为什么：控制台**只读配置、不回写**，所以删/加模型都不会改变工作台实际用的模型。
用户以为"换个模型"成功了，实际没有——这是最容易产生"这 AI 真笨"的误会。

### E4 · 启动器窗口 → 一行提示（**已实现，v1.3.7**）

位置：`scripts/start-local-ai.mjs` 启动成功后的横幅里加一行：

```
   觉得回答变短 / 长对话跑偏？
   打开「本地AI控制台」→ 体检
```

为什么：这行字出现在**用户每天都会看到的位置**，而且不占额外操作。

### E5 · 出错页 → 补一条"能聊但不对"的分支

位置：`ui/app.js` 的 `errHow`。

现在的补救动作只针对安装失败。应补一类：能启动、能对话，但**回答短/重复/跑偏**，
补救动作指向「控制台 → 体检」而不是「重装」。

### E6 · 使用界面（工作台）→ 嵌入不了，要绕

这是本次审计最关键的结论，见 V2。工作台是 DeepSeek Harness 的网页，
配置在磁盘上的 `~/.dsh/profiles/web/cordis.patch.yml`，
**改配置必须重启服务**，而工作台自己没有重启入口。

可行的绕法只有两个：
1. 在工作台**之外**给入口（E2/E4），这是本次建议的方案；
2. 给 dsh 写插件做 `/health` 斜杠命令——需要 dsh 插件开发，不在本仓库范围。

## 4. 发现的问题（按严重度）

### P1 · 体检工具跑不起来（高，已修）

走完一键安装的用户有 Node、没有 Python。原方案 `python healthcheck\run_all.py` 直接失败，
而 Windows 的 `python` 还是个跳转微软商店的假别名——用户会以为是工具坏了。

**修复**：新增 `healthcheck/quick.mjs`（Node 原生，零依赖，用内置 `fetch`）。
`run_all.py` 保留给开发者（功能更全：SVG 曲线、拐点、多 seed）。

### P2 · 删掉当前模型会陷入死循环（高，已加护栏）

`/api/delete` 不检查是否是当前配置模型，而控制台又不回写配置：

```
删掉正在用的模型 → 启动失败（precheckModel 只警告，不修）
                → 回控制台装个新的 → 配置仍指向被删的 → 还是失败
```

**修复**：删当前模型时返回 409，并明确告诉用户"先重跑安装向导换模型"。

### P3 · 加装模型不会切换 / 改上下文要重跑向导（高，**已修**）

`/api/pull` 只下载，不改 `配置.json`；改上下文也只能重跑向导。

**修复（v1.3.6）**：控制台新增「上下文与模型」页，可直接改模型 / 窗口 / 输出上限 /
压缩三项，实时显示压力预算，应用前备份。`/api/pull` 本身仍不自动切换——
用户在「上下文与模型」页选一下即可，比弹窗打断更可控。

### P4 · 使用界面无配置入口（中高，本仓库已用控制台绕开）

见 V2。工作台本身仍改不了，但控制台现在能改（v1.3.6），用户不必再重跑向导。

### P5 · 完成页文案与实际不符（低，已修）

`ui/index.html:190` 写"以后就用桌面上的**两个**图标"，实际创建**三个**（多了控制台）。
用户会不知道控制台的存在，而控制台正是唯一能长期操作的地方。

### P6 · 「首分歧」语义错误（中，已修）

`first_divergence` 在"一方是另一方前缀"时返回较短长度，导致输出自相矛盾：

```
首分歧=451   翻转率=0.0%     ← 长度不同，不是分歧
```

**修复**：前缀情况返回 `-2`，显示为 `len≠`，且不计入 onset 判定。Python / Node 两版同步。

### P7 · 阶梯会超出实际窗口（中，已修）

阶梯写死 8K/16K/32K，但模型实际 `num_ctx` 可能只有 16384。
超出的那档会被 Ollama **静默截断**，测出来的"零漂移"是假的。

**修复**：`effectiveContext()` 先读 `配置.json`，再问 Ollama `/api/ps` 的 `context_length`，
超出上限的档位自动跳过并说明原因。实测本机：窗口 32768 → 上限 31744 → 32K 档被跳过。

### P8 · 报告目录名多一个点（低，已修）

`toISOString().replace(...).slice(0,15)` 把毫秒的小数点留下了，生成 `20261018112556.`。
